**IBM watsonx.ai.** The interpretation agent calls watsonx.ai for a Granite
second opinion on each patient reply. The integration is in `bridge/llm.py` and
activates when `WATSONX_API_KEY`, `WATSONX_URL` and `WATSONX_PROJECT_ID` are
present in the environment. The design constraint is deliberate and enforced in
code: Granite may raise a concern level, never lower one, and it is never asked
to resolve an ambiguous reply. Without credentials the system falls back to its
deterministic rule engine, which is what makes the published evaluation
reproducible by anyone who clones the repository. [State whether the submitted
demo was run with watsonx credentials or on the rule engine.]

**IBM watsonx Orchestrate.** Orchestrate is the intended host for the seven
agents and the daily cycle. [State what you actually did there, for example
which agents were defined, or that the team requested the instance and modelled
the cycle locally in `bridge/orchestrator.py` without deploying.]

**Everything else.** Python 3 standard library only, with SQLite for per
patient state and the append only audit log, a small TF IDF passage index over
the discharge guidance corpus for retrieval grounding, and a standard library
HTTP server for the nurse worklist. No third party packages, so the prototype
clones and runs with one command.

**Data.** Synthetic throughout. The cohort, the replies and the plan status
feeds are all generated by `bridge/synth.py`. No personal information, no
client data and no real patient record is used at any point. Ground truth for
the evaluation is held in `eval/ground_truth.json` and is never read by any
agent.
